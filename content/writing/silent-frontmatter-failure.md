新文章推上去，构建成功，页面 200，样式正常。只有一个小小的不对劲：它没出现在列表的最前面。

往下翻，在归档的最后一年，夹着一篇日期显示为 `0001.01.01` 的文章。

## 我以为的原因，和实际的原因

第一反应是日期格式。我平时手写 `2026.10.28` 这个点号格式，看着顺眼，但 Go 的日期解析要的是连字符。

于是做了个对照实验，写两篇坏文章：一篇 date 写成点号，一篇把 date 整行删掉。

结果和我的预期相反。

| 坏法 | Hugo 退出码 | 页面 | 线上表现 |
|---|---|---|---|
| `date: 2026.10.28`（点号） | **1** | 仍生成 | 构建失败，不会部署 |
| 整个 `date:` 行漏掉 | **0** | 生成 | **日期 0001.01.01，静默上线** |
| 整个 `title:` 行漏掉 | **0** | 生成 | **标题空白，静默上线** |
| 整个 `summary` 漏掉 | **0** | 生成 | 列表页副标题空白 |

Hugo 对格式错误是严格的——它认识 `date` 这个键，发现值不是合法日期，会打 `ERROR ... is not a parsable date` 并返回退出码 1，CI 直接红掉。

但**字段整个不存在时，它认为你没打算用这个字段**，用零值填上，什么都不说。

这就是那次上线的原因：我从另一篇文章复制骨架时，把 `date` 那一行连着删掉了。多删一行比写错一个字符容易得多。

## 为什么这比构建失败危险

构建失败是安全的：CI 红了，东西上不了线，你被迫修。

静默失败不一样。它能通过构建、能上线、能被 RSS 抓走，然后你的文章在归档里排到了公元 1 年。等你发现的时候可能已经过了几周，RSS 读者早就看到了一条顺序错乱的推送。

第三类更隐蔽，是 YAML 自己的问题：

```yaml
# 这行会让整个 frontmatter 解析失败
title: 一次 500 的排查: 从日志到根因

# 正确：给整行加引号
title: "一次 500 的排查: 从日志到根因"
```

英文冒号加空格是 YAML 的映射分隔符。这种情况下 Hugo 会报 `mapping value is not allowed in this context`——报错信息是对的，但它指向文件第 2 行第 8 列，也就是冒号的位置，不会告诉你"因为标题里有个冒号"。

## 所以校验要盯的不是格式，是存在性

这套博客的文章是生成后直接落盘的，没有人逐篇校对。所以"靠人工检查"不成立——**必须让错误在构建阶段就变成硬失败**。

加了一个不依赖任何第三方库的脚本，`hugo` 之前跑。它只做一件事：把"能上线但不正确"的状态改成"不能上线"。

```js
const REQUIRED = ['title', 'date', 'summary', 'tags'];

for (const file of files) {
  const fm = readFrontmatter(file);
  for (const key of REQUIRED) {
    // 格式错误 Hugo 自己会拦，缺失只有这里能拦
    if (!(key in fm) || fm[key] === '') fail(file, `缺少必需字段 ${key}`);
  }
  if (!Array.isArray(fm.tags) || fm.tags.length === 0) {
    fail(file, 'tags 必须是非空数组');
  }
}
```

条目不多，但每一条都对应一次实测出来的静默失败：

- `date` 缺失 → 零值排序，退出码还是 0
- `tags` 缺失 → 模板在 `delimit .Params.tags` 处炸掉，但报错指向 `single.html:26`，不说哪篇文章缺
- `tags` 写成字符串 → 同样的模板爆炸
- `summary` 缺失 → 列表页副标题、`meta description`、RSS 描述同时变空

> 判断一条规则该不该加，问一个问题：**如果这个字段错了，构建会不会失败？** 会，交给工具；不会，自己拦。能上线但不正确的状态，比不能上线难处理一个数量级。
